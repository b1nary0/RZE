# Utils Library Reference

`Utils` (`RZE/Utils/`) is the foundational layer of the entire stack — it has **zero dependencies** on any other RZE project (`Utils.sharpmake.cs` has no `AddPublicDependency` calls at all). Everything else, directly or transitively, depends on it. Built as a static Lib with a precompiled header (`Src\UtilsPCH.h`/`.cpp`, see [Sharpmake-Project-Graph.md](../09-BuildSystem/Sharpmake-Project-Graph.md#precompiled-headers)), which holds the std, Utils core and Utils math headers every project shares (`EnginePCH.h` includes it first). **GLM** is the math library RZE's own Vector/Matrix/Quaternion types wrap; only `Utils/Math` includes it, each file the GLM headers it uses.

## Primitives & containers

- `PrimitiveDefs.h` — canonical fixed-width typedefs used everywhere: `Int8/16/32/64`, `Byte`/`U8/16/32/64`, `Float32/64`.
- `Utils.h` — `ContainerUtils::VectorEraseBack` — O(1) unordered erase (swap-with-back, then pop) used throughout the Engine (e.g. `RenderEngine`'s object containers) instead of `std::vector::erase`, which would shift elements.
- `Functor.h` — `template<TReturnType, class...Args> class Functor` — a copyable/movable wrapper around `std::function`, used pervasively for input-event callbacks, component factories, and job tasks.
- `StringUtils.h` — `StringUtils::ExtractFileNameFromPath`, `StringUtils::FormatString<Args...>` (sprintf-style formatting into a `std::string`, fixed 1024-char buffer), `Trim` (spaces and tabs at either end), ASCII case helpers: `ToLower` / `ToUpper`, `EqualsIgnoringCase`, `StartsWithIgnoringCase` / `EndsWithIgnoringCase`, and `ContainsIgnoringCase(text, part)` (true for an empty part; the Object Inspector's filters and Task History's search use it), and `CopyTruncated(destination, source)`, which copies into a fixed `char` array, cutting the text short to fit (what MSVC's `strncpy_s(..., _TRUNCATE)` did, on every compiler).
- `TimeUtils.h/.cpp` — times for people: `FormatTimeAgo(time, now)` ("Just now", "5 minutes ago", "Yesterday", a date once it's a month old; the file tiles use it), `FormatClockTime(time)` (the local time of day, "15:56:32"), and `FormatDuration(seconds)` (short: "8s", "1m 05s", "2h 03m"; task times and time left).
- `StatsWindow.h/.cpp` — groups frames into half-second windows (`k_windowSeconds`) for stats shown to people, so they update a couple of times a second and stay readable. A frame runs from one `AddFrame(now)` to the next, and the first only starts the window. `AddFrame` returns true when the window closes; the owner keeps its own sums and turns them into averages with `PerFrame(total)` and `PerSecond(count)`, which describe the window that just closed. `FramePacer` (`FrameStats`), `RenderEngine` (`RenderStats`) and the render thread (`Rendering::RenderThreadStats`) use it.
- `LiveIDAllocator.h/.cpp` and `LiveObjectPtr.h/.cpp` — lifetime-checked handles. `LiveIDAllocator` hands out IDs that are never reused and says which are alive. `LiveObjectPtr<T, TLifetime>` is a copyable, non-owning handle (a pointer plus the object's ID); `UniqueLiveObjectPtr<T, TLifetime>` is the move-only one, for the single holder that destroys the object, and a const one gives only const access. Once the object is destroyed a handle equals `nullptr`, and debug builds assert if it's used. Handles compare with each other by ID, and with a raw pointer from either side: equal only while the object is alive and is that object. `TLifetime` is a policy with `IsAlive(id)` and `GetID(object)`. A handle is made explicitly from any live object, and moving one leaves the source null. `GameObjectPtr`, `GameObjectComponentPtr<T>`, `RenderObjectPtr` and `LightObjectPtr` are aliases of these ([Scene-And-GameObject-Model.md](../03-SceneAndGameObjects/Scene-And-GameObject-Model.md#handles-gameobjectptr-and-gameobjectcomponentptrt)).
- `Conversions.h/.cpp` — string conversions (`IntFromString`, `StringFromInt`, resource keys from paths). `StringToWString`, which only Windows APIs need, is `Platform/Windows/WideStrings.h`.
- There's no GUID helper: object IDs are `ObjectGUID` ([Scene-And-GameObject-Model.md](../03-SceneAndGameObjects/Scene-And-GameObject-Model.md)). The old Win32 `GUIDHelper` had no users and was removed.

## Math (`Math\`): thin wrappers over GLM

All spatial values follow [World-Conventions.md](../02-Architecture/World-Conventions.md): metres, right-handed, +Y up, degrees for anything a person sees.

**Convention: glm stays inside these classes.** Code outside `Utils\Src\Utils\Math\` uses `Vector2D/3D/4D`, `Matrix4x4`, `Quaternion` and the `MathUtils` / `VectorUtils` helpers, never `glm::` types or `GetInternalVec()` / `GetInternalMat()` / `GetInternalQuat()`. When something is missing, add a method or helper here rather than reaching for glm. The other way round, the math classes only get mathematical helpers: one that just puts them together for one area (e.g. a cube face's view, which follows D3D's cube layout) goes in that area's namespace, built on their public API.

| File | What's in it |
|---|---|
| `Units.h` | The conventions themselves (as a comment), `Units::Metre / Centimetre / Millimetre`, and `WorldAxes::Right() / Up() / Forward()` (+X, +Y, −Z). |
| `Math.h/.cpp` | `MathUtils`: `Pi`, `ToRadians` / `ToDegrees` (constants to multiply by: `degrees * MathUtils::ToRadians`), `Clamp` / `Clampf`, `SmoothStep(t)`, `CeilPowerOfTwo`. `VectorUtils`: `kEpsilon` / `kEpsilonSq`, `Dot`, `Min` / `Max` (component-wise), `Lerp`, `Slerp`, `DistanceSq`. |
| `Vector2D`, `Vector3D`, `Vector4D` | Wrap `glm::vec2/3/4`. Usual arithmetic, `Normalize` / `Normalized`, `Cross`, `Length` / `LengthSq`, `GetValuePtr()` (const and non-const) hands the components to float-array APIs like ImGui and ImGuizmo. `Vector4D(xyz, w)` and `XYZ()` convert between 3D points and homogeneous coordinates. |
| `Matrix4x4.h/.cpp` | Wraps `glm::mat4` (column-major). Builders: `CreateInPlace(position, scale, eulerDegrees)`, `CreateViewMatrix`, `CreatePerspectiveMatrix` / **`CreatePerspectiveMatrixZeroToOne`** (use this one: D3D's 0..1 depth), `CreateOrthoMatrix` / `CreateOrthoMatrixZeroToOne`, `CreateSubRectProjection(ndcMinX, ndcMinY, ndcMaxX, ndcMaxY)` (narrows a projection to part of the view; used by marquee selection and picking). Instance: `Translate`, `Rotate(angleRadians, axis)`, `Scale`, `Inverse`, `Transpose`, `GetPosition` / `GetRotation` / `GetScale`, `GetRow(i)` (as it multiplies a column vector), `GetValuePtr()`, `operator*` with matrices and `Vector4D`, `IDENTITY`. |
| `Quaternion.h/.cpp` | Rotations. Built from `eulerRadians`, `FromEulerDegrees`, `FromAngleAxis(angleRadians, axis)` or the rotation between two vectors; `ToEulerDegrees()`, `ToAngleRadians()`, `ToAxis()`, `Inverse()`, `Normalized()`, multiplication by quaternions and vectors. |
| `Plane.h/.cpp` | `Plane(normal, distance)`, or from `ax + by + cz + d` coefficients (`Vector4D`). `SignedDistance(point)` is positive on the side the normal points to. |
| `BoundingBox.h/.cpp` | An axis-aligned box. **Empty when made with no arguments**: it holds nothing, and growing it by a point or box makes it exactly that (`IsEmpty()`; growing by an empty box changes nothing). `Around(points)`, `GetCentre`, `GetSize`, `GetRadius` (half the diagonal), `GetCorners` / `GetTransformedCorners(matrix)`, and `Transformed(matrix)`: the axis-aligned box around it once transformed, worked out from the matrix (Arvo's method) instead of 8 corners, for affine transforms. `Intersects(box)`: whether two boxes share any point, touching faces included; an empty box intersects nothing. Used for render object, scene and hierarchy bounds, culling and framing. |
| `Frustum.h/.cpp` | The six planes of a view volume, taken from a view-projection matrix with D3D's 0..1 depth (Gribb & Hartmann), each normal pointing inwards. `Intersects(box)` is false only when the box is wholly outside one plane (or empty), so a box just off a corner can still pass, which is fine for culling. Used for frustum culling, the pick pass and marquee selection. |
| `Ray.h/.cpp` | A half-line: `GetOrigin`, `GetDirection` (normalised by the constructor), `GetPoint(distance)`, and `Intersect(plane)`: the point where it meets a `Plane` ahead of its origin, if it does, never when (nearly) parallel. |
| `ViewProjection.h/.cpp` | From a view's pixels back to the world, for a view-projection matrix with D3D's 0..1 depth. `Unproject(clipSpace, viewSize, pixel, depth)` gives the world position drawn at a pixel and depth: pixel to NDC, then the inverse matrix, then dividing by the result's w. `GetRay(clipSpace, viewSize, pixel)` is the ray from the near plane through the pixel. Pixels count from the top-left, y down, with a pixel's centre at +0.5. Used by the Editor's `ScenePicker` to place dropped meshes. |

## Platform (`Platform/`)

**How per-platform code is laid out.** A neutral header (`Shell.h`, `Process.h`, `FolderWatcher.h`, `Timers/PreciseSleep.h`, `TypeNames.h`, and the OS half of `DebugUtils/Debug.h`) is implemented once per platform, in `Platform/Windows/<Name>Windows.cpp` and `Platform/Linux/<Name>Linux.cpp`. Only the platform's folder is compiled ([Sharpmake-Project-Graph.md](../09-BuildSystem/Sharpmake-Project-Graph.md)), so callers include the header and never see the OS. Helpers only one platform uses get its suffix too (`Windows/WideStrings.*`, `Linux/SpawnProcessLinux.*`). See [Platforms-And-Graphics-APIs.md](Platforms-And-Graphics-APIs.md).

- `Platform.h` — the few things that can't be hidden behind a function: `RZE_PLATFORM_WINDOWS` / `RZE_PLATFORM_LINUX`, `RZE_DEBUG_BREAK()` (stops in the debugger at the line it's written on), `RZE_PRAGMA_OPTIMIZE_OFF/ON` (the compiler's pragmas behind `RZE_DISABLE_OPTIMIZATION`), `Platform::k_pathSeparator` / `k_otherPathSeparator`, `k_executableSuffix` (`.exe` or nothing), `k_buildGameScript` (`BuildGame.bat` or `BuildGame.sh`), and `Platform::LocalTime` (MSVC's `localtime_s` and POSIX's `localtime_r` take their arguments in opposite orders). It and Rendering's `GFXDeviceFactory.cpp` are the only first-party files that check the platform with the preprocessor.
- `Filepath.h/.cpp` — `class Filepath`: stores both `m_relativePath` and `m_absolutePath`. `EDirectoryContext { Runtime, Source }` — a static, **process-wide** context switch (`Filepath::SetDirectoryContext`) that changes how relative paths resolve. `Source` resolves against the source tree: the folder above `_build\`, or beside the executable when it isn't under `_build\`. The Editor (`EditorMain.cpp`), the Game (`Game\Src\Main.cpp`) and `SourceAssetBurnerMain.cpp` all set it, so they read `Assets\`, `Config\` and `ProjectData\` in place and nothing is copied into `_build`. `Runtime` (beside the executable) is kept for a future packaged game. The context is read when a `Filepath` is built, so one built during static initialisation resolves before `main` sets it; build paths when they're used. Also: `CreateDir`, `FromAbsolutePathStr`, `Exists`, `GetAbsolutePath`/`GetRelativePath`, `GetAbsoluteDirectoryPath`/`GetRelativeDirectoryPath`, `IsValid`. `==` and `!=` compare relative paths exactly, so case counts (a rename that only changes case is a change), unlike `IsInside`, which ignores it.
  - **Separators.** Paths in memory use the platform's separator (`\\` on Windows, `/` on Linux), and either is accepted when a `Filepath` is made, so paths written on Windows (in scene files, `-scene` arguments, model files) work on Linux. `GetSerializedPath()` is the relative path with `\\` on every platform, which is what scene files store, so a scene saves the same on both.
- `File.h/.cpp` — `class File` wraps `std::ofstream` with an `EFileOpenMode` (`Append`/`AtEnd`/`Binary`/`Read`/`Write`/`Truncate`/`Closed`, mapped onto `std::ios_base::openmode`), templated `Overwrite<T>`/`Write<T>`, `operator<<`, `Content()`. For writing a file so readers never see half of it: write to `File::GetTemporaryPathFor(path)` (the path plus `.tmp`), then `File::MoveReplacing(temporary, path)` renames it over the old file in one step. It returns false if it couldn't (e.g. the file is open elsewhere) and removes the temporary file either way. Scene saves and PNG writes use it.
- `File::Move(from, to)` moves or renames a file or folder unless something is already at `to`; a change of case only is allowed. It returns false, moving nothing, if it couldn't. The Content Browser's renames use it.
- `FileNames.h/.cpp` — the rules for naming files, and what a typed name means as a path: `GetError(name)` (empty, characters Windows can't use, device names like `CON`), `WithExtension`, `MakeUnique(folder, name)` ("New Folder 2"), `ParseExtensionFilter("*.meshasset")`, `MatchesExtensions(name, extensions)` (ignoring case; file filters and drag targets use it), and `ResolveSave` / `ResolveRename`, which turn a typed name into a path or the reason it can't be used. Windows' rules apply on every platform, so a project made on Linux still works on Windows:
  - **`IsTaken(path, itself)`**: whether something in the folder already has the name **ignoring case**, as Windows would see it, except the file itself (so renaming `Tank` to `TANK` isn't taken). `MakeUnique` and the renames use it.
  - **`FindIgnoringCase(path)`**: the file on disk with that name in any case, an exact match first, as Windows would open it; invalid if there's none. For names in data written on Windows, e.g. a texture an `.mtl` names `controls.tga` that's `Controls.tga` on disk (the asset importer uses it).
- `Folders.h/.cpp` — `Folders::ListSubfolders(folder)` (by name) and `FindFiles(folder, extension)` (recursive).
- `FolderWatcher.h` — whether anything in a folder or under it changed (a file or folder made, renamed or deleted, or a file written), not what. `PollChanged()` doesn't wait, so there's no thread behind it; the OS tells of a change soon after, and may tell of several as one. The Editor's `ProjectWatcher` watches `Assets` and `ProjectData` with it. Move-only. Windows uses a change notification on the folder tree; Linux uses one inotify instance per watcher, with a watch on each subfolder (inotify isn't recursive), added as folders appear. If the user's inotify instances run out, it says so and the Editor's Refresh still works.
- `Shell.h` — the desktop's file manager and trash, kept out of the Editor: `ShowInFileBrowser(path)` (the file selected, or the folder open) and `MoveToRecycleBin(path)`, plus `GetFileBrowserName()` and `GetRecycleBinName()` for the UI's text ("Explorer" and "Recycle Bin" on Windows, "File Manager" and "Trash" on Linux).
  - Windows: `ShellExecute` of Explorer with `/select`, and `SHFileOperation` with undo.
  - Linux: the freedesktop `FileManager1` D-Bus interface (`ShowItems` for a file, `ShowFolders` for a folder), on a thread of its own so the UI never waits for a file manager to start, falling back to `xdg-open`.
  - Linux trash: the freedesktop.org Trash spec, done in `ShellLinux.cpp` rather than through a desktop's tools, so it works on any distro and desktop. A file on the home folder's filesystem goes to `$XDG_DATA_HOME/Trash` (or `~/.local/share/Trash`); one on another drive goes to that drive's own trash, `$topdir/.Trash/$uid` when an administrator made a shared `.Trash` with the sticky bit, or else `$topdir/.Trash-$uid`, since trashing is a rename and never a copy. Its `info/<name>.trashinfo` is made first, with `O_EXCL`, so two programs can't take the same name (a taken one becomes `Name.2.ext`); it holds the percent-encoded `Path=` (absolute in the home trash, relative to `$topdir` on another drive) and the local `DeletionDate=`. Then the file is renamed into `files/<name>`; if that fails, the `.trashinfo` is removed. A failure logs a warning saying why.
- `Process.h` — this program's path (`GetExecutablePath()`, found once), and running others: `RunScript(script, onOutputLine, shouldStop, outExitCode)` runs a script on the calling thread with no console window, passing each line of its output on (Windows: `cmd.exe`; Linux: `/bin/sh`, so the script needs no execute bit), and `Start(executable, arguments)` starts one without waiting. `GameBuilder` uses both.
- `Timers/PreciseSleep.h` — sleeps for a precise length of time (the frame pacer's), the OS's sleep covering most of it and a short spin the rest: a high-resolution waitable timer on Windows, `clock_nanosleep` on Linux.
- `TypeNames.h` — `TypeNames::Get(typeid(T))`: a type's name as the code spells it, with its namespaces. `type_info::name()` is each compiler's own: MSVC's is `"class RenderComponent"` (Windows strips the `class `), and clang's the mangled `"15RenderComponent"` (Linux demangles it). Component names, which the Object Inspector shows, come from it.
- `CmdLine.h/.cpp` — `CmdLine::Arguments::Initialize(argv, argc)`, `Get(name, out std::string_view)` and `GetInt(name, out int)`: simple `-flag value` command-line parsing, used for `-scene` (Editor, Game), `-console` (engine) and `-launchMonitor` (engine).
- `Timers\HiResTimer.h/.cpp` — high-resolution timer backing `START_TIMED_BLOCK` in `Debug.h`.

## Debugging (`DebugUtils\`)

- `DebugConfig.h` — which debugging aids a build has: `RZE_ASSERTS_ENABLED`, `RZE_LOGGING_ENABLED`, `IMGUI_ENABLED`, `RZE_GFX_VALIDATION_AVAILABLE` (and `RZE_GFX_VALIDATION_BY_DEFAULT`, Debug only) and `RZE_OPTIMIZATION_SWITCH_ENABLED`, each defined unless `RZE_RETAIL` is. Small, so a header that only needs to know (`LiveObjectPtr.h`) can include it without `Debug.h`.
- `Debug.h/.cpp` — the log and its levels, asserts, `START_TIMED_BLOCK` and `RZE_DISABLE_OPTIMIZATION`; the OS half in `Platform/Windows/DebugWindows.cpp` and `Platform/Linux/DebugLinux.cpp`. See [Debug-Services-And-Logging.md](Debug-Services-And-Logging.md).

## Interfaces

- `Interfaces\Resource.h` — `class IResource`: `virtual bool Load(const Filepath&)`, `virtual void Release()`. An in-memory image is loaded with `Texture2D::Load(TexelBuffer&&, width, height)` instead, on the texture itself. This is the contract `ResourceHandler` and every loadable resource type (`StaticMeshResource`, `EngineConfig`, texture resources) build on. It also has optional hooks for asynchronous loading (`SupportsAsyncLoad`, `LoadCPU`, `RequestDependencies`, `GetNextFinalizeStepCost`, `FinalizeStep`, and `GetFinalizeProgress` for progress displays). See [Asset-Import-Runtime.md](../05-AssetPipeline/Asset-Import-Runtime.md).

## Reflection (`Reflect\`) — a second, separate reflection system

- `Reflection.h` — macros `REFLECT_REGISTER_COMPONENT(Type)` / `REFLECT_REGISTER_COMPONENT_CHILD(Type, ParentType)` (used by `EditorCameraComponent`'s constructor), and `REFLECT_NAME(Type)`.
- `ReflectDB.h/.cpp` — `class ReflectDB` (all-static): `RegisterComponent(typeStr)`, `RegisterComponentChild(typeStr, parentTypeStr)`, `GetIDFromName(typeName)`. Keeps `std::unordered_map<ReflectTypeID, ReflectTypeDescriptor>` where `ReflectTypeDescriptor { name, typeID, parentTypeID, children }`. `ReflectTypeID` is generated via `std::hash<const char*>` on the type-name string.

**This system is independent of, and not the same as,** the `GameObjectComponentRegistry`/`GameObjectComponentTypeID` system described in [Component-System.md](../03-SceneAndGameObjects/Component-System.md) — that system drives serialization/factory IDs; `ReflectDB` is used only for the Editor's inspector sort-ordering today (`EditorCameraComponent` calls both `REGISTER_GAMEOBJECTCOMPONENT` machinery *and* `REFLECT_REGISTER_COMPONENT_CHILD` for different purposes). See [10-KnownIssues](../10-KnownIssues/Architectural-Notes-And-TODOs.md) for a note on a latent risk in `ReflectDB`'s use of `std::hash<const char*>`.
