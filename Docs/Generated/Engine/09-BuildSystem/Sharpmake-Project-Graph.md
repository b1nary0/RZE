# Sharpmake Project Graph

RZE's Visual Studio solution is generated by [Sharpmake](https://github.com/ubisoft/Sharpmake) — a C#-based build config generator (conceptually similar to CMake/Premake) — rather than hand-maintained `.vcxproj`/`.sln` files. This page details the actual Sharpmake definitions; for the high-level dependency picture see [Module-Dependency-Graph.md](../02-Architecture/Module-Dependency-Graph.md).

## Generation flow

```
RZE\GenerateSolutions.bat
  -> "../Tools/Sharpmake/Sharpmake.Application.exe" "/sources('RZE.sharpmake.cs')"
  -> generates RZE.sln + per-project .vcxproj files under RZE\_project\
```

`RZE.sharpmake.cs` is the solution root:
```csharp
[module: Sharpmake.Include("Make/Sharpmake/CommonTarget.sharpmake.cs")]
[module: Sharpmake.Include("Make/Sharpmake/BaseProject.sharpmake.cs")]
[module: Sharpmake.Include("Make/Sharpmake/Sharpmake.sharpmake.cs")]
[module: Sharpmake.Include("Engine/Engine.sharpmake.cs")]
[module: Sharpmake.Include("Utils/Utils.sharpmake.cs")]
[module: Sharpmake.Include("SourceAssetBurner/SourceAssetBurner.sharpmake.cs")]
[module: Sharpmake.Include("Externals/Externals.sharpmake.cs")]
[module: Sharpmake.Include("Modules/Rendering/Rendering.sharpmake.cs")]
[module: Sharpmake.Include("Editor/Editor.sharpmake.cs")]
[module: Sharpmake.Include("Game/Game.sharpmake.cs")]

public class RZE : Solution {
    // registers all 7 native projects + SharpmakeProjectBase against CommonTarget
}
```

`Main.SharpmakeMain` pins the Windows SDK/DevEnv (`vs2017`, Kits Root `10.0.18362.0`) and calls `arguments.Generate<RZE>()`.

## Shared build config

- **`Make\Sharpmake\CommonTarget.sharpmake.cs`** — defines `CommonTarget : ITarget`: `SubPlatformType` (only `x64` is active — macOS/UWP are present in the enum but commented out / throw `NotImplementedException` if requested), `Mode` (only `Game` is active — an `Editor` mode value exists but is commented out, meaning the Editor/Game split today is by separate executable project, not by a Sharpmake target axis), `Optimization` (Debug/Release/Retail), DotNet framework `v4_8`.
- **`Make\Sharpmake\BaseProject.sharpmake.cs`** — abstract `BaseProject : Project` that every native project derives from. Sets `SourceRootPath = "Source"`, project output paths (`_Project/[project.Name]_[target.Platform]`), binary output to `_Build/[target.Name]/`, standard include paths (project's own `Src` + `ThirdParty/Include`). `ConfigureWin64` sets C++17, RTTI on, Unicode charset, exceptions on, warning level 3 + warnings-as-errors (with warning 4267 disabled), `NOMINMAX` defined. Debug/Release/Retail configs set the runtime library and inlining/optimization (Retail additionally enables AVX2, max speed, SEH exceptions).
- **`Make\Sharpmake\Sharpmake.sharpmake.cs`** — `SharpmakeProjectBase : CSharpProject`, the C# project wrapping Sharpmake itself inside the generated solution (in a "Tools" solution folder), referencing `Tools\Sharpmake\Sharpmake.dll`/`Sharpmake.Generators.dll` directly — this is what lets you edit and regenerate the solution from inside Visual Studio without leaving the IDE.

## Per-project Sharpmake files

| Project | File | Output type | `AddPublicDependency<T>` (explicit only) | Extra linked libs |
|---|---|---|---|---|
| Utils | `Utils\Utils.sharpmake.cs` | static Lib | *(none)* | — |
| Externals | `Externals\Externals.sharpmake.cs` | static Lib | *(none)* | — |
| Modules/Rendering | `Modules\Rendering\Rendering.sharpmake.cs` | static Lib | Externals, Utils | `d3d9`, `d3d11`, `d3d12`, `dxgi`, `d3dcompiler`, `DirectXTK`, `OptickCore` |
| Engine | `Engine\Engine.sharpmake.cs` | static Lib | Utils, Externals, Rendering | `OptickCore`; copies `ThirdParty\Dll\x64\*.dll` to output post-build |
| SourceAssetBurner | `SourceAssetBurner\SourceAssetBurner.sharpmake.cs` | exe | **Engine only** | `assimp` |
| Editor | `Editor\Editor.sharpmake.cs` | exe | **Engine only** | `assimp` |
| Game | `Game\Game.sharpmake.cs` | exe | **Engine only** | — |

All three executables — `Editor`, `Game`, and `SourceAssetBurner` — have converged on declaring a single explicit dependency, `Engine`, rather than also separately declaring `Utils` (and, for `Game`, `Rendering`). This isn't a behavior change: `Engine` itself has `AddPublicDependency<Utils>`/`<Externals>`/`<Rendering>`, and Sharpmake's `AddPublicDependency` propagates a project's public include/lib paths to everything that depends on it — so all three still get full access to `Utils`/`Rendering` headers/libs, just transitively through `Engine` instead of via their own separate declaration.

A couple of things worth knowing if you're auditing this yourself:

- `SourceAssetBurner`'s explicit `AddPublicDependency<Utils>` was the last holdout and has since been removed. This table reflects the current state as of the last check — if the build config keeps getting cleaned up, re-verify against the actual `.sharpmake.cs` files rather than trusting this table indefinitely.
- Both `Editor` and `SourceAssetBurner` additionally have a raw `conf.IncludePaths.Add(Path.Combine(Globals.RootDir, "Utils"))` line pointing at the `Utils` project root (not `Utils\Src`). Given the transitive path already resolves correctly, this line looks vestigial rather than necessary.

Engine and Utils both use a precompiled header (`StdAfx.h`/`.cpp`).
